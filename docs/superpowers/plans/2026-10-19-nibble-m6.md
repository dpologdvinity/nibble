# nibble M6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make nibble fast on this CPU — AVX2/FMA/F16C and AVX-VNNI kernels, a tiled prefill GEMM, fused ops and tuned threading — and prove every step with a benchmark harness, a bandwidth roofline and a llama.cpp comparison (spec §5.4–5.5, milestone M6).

**Architecture:** The scalar kernels in `src/backend/cpu/ref_ops.cpp` stay as the correctness oracle. SIMD kernels live beside them (`src/backend/cpu/simd/`), selected at compile time (`-march=native`, spec §5.2), each tested against its scalar twin. `nibble bench` measures `pp512`/`tg128`, a streaming-read bandwidth ceiling and a thread sweep; `tools/bench_llamacpp.sh` runs `llama-bench` with matching settings. Every ladder step records results to `bench/results/` and the README charts them.

**Tech Stack:** unchanged C++20 toolchain; x86 intrinsics (`<immintrin.h>`); stdlib-only Python for SVG charts.

**Spec:** `docs/superpowers/specs/2026-10-17-nibble-design.md` (§5 kernels and performance, §8.4 performance tests, §9 M6). Deferred minors: `docs/superpowers/plans/2026-10-18-nibble-m5-ledger.md`.

## Decisions this plan makes (for review)

1. **Compile-time ISA only** (`-march=native` by default, scalar fallback when the features are absent or `-DNIBBLE_SIMD=OFF`). No runtime CPU dispatch — spec §5.2 leaves that to a later "tool" phase. CI gains a native-ISA job so the SIMD code is built and tested there too.
2. **Scalar reference kernels stay the oracle** and are compiled with `-ffp-contract=off`, so they give identical results on g++ and clang (resolves the M4/M5 deferred FMA item).
3. **The SIMD Q8_0 activation quantizer must be bit-identical to the scalar one** (which is bit-identical to llama.cpp's reference). SIMD dot products and F16/F32 matmuls may reorder float sums: tested against scalar within 1e-5 relative; all e2e gates unchanged (F16 0.999, quantized 0.995 + 90%).
4. **Benchmark protocol:** median of ≥ 5 repetitions after 1 warm-up, same thread count for nibble and llama.cpp, run back-to-back in one session, with the 1-minute load average recorded beside every number. Results that ran with load average > 2 are flagged "noisy" in the report and charts (this machine is often shared).
5. **Speed target (spec §1):** `tg128` on Qwen2.5-0.5B Q4_0 within 1.5× of llama.cpp CPU on this machine; matching is a stretch goal. `pp512` is reported without a target.
6. **F16 weights keep F32 activations** (F16C converts weights on the fly) rather than llama.cpp's F16 activation conversion — keeps the F16 e2e gate where it is.
7. **Charts are SVG files generated by a stdlib-only Python script** (`bench/plot.py`) and committed (`docs/bench/*.svg`), so the README needs no build step or plotting dependency.

## Global Constraints

- All M0–M5 constraints hold (C++20; `-Wall -Wextra -Wpedantic -Werror` on g++ 13 and clang 18; untrusted GGUF; `nibble::Error` with escaped text; model code never dereferences activations; Conventional Commits ≤ 72 chars, no trailers; models/goldens never committed).
- **No allocation in `Transformer::forward` or `Sampler::sample`** — now enforced by a test that counts `operator new` across a full decode step (Task 2).
- Every SIMD kernel has a scalar twin and a test comparing them on random inputs including tails (lengths not a multiple of the vector width / block size), unaligned pointers and edge values (zero blocks, max-magnitude values).
- E2E gates and goldens unchanged; the full e2e suite must pass after every task that touches a kernel.
- Benchmark numbers in the README must come from committed `bench/results/*.jsonl` files; never hand-typed.
- Work on branch `feat/m6`. Do not push.

## Review Focus

1. **Tails and odd sizes:** row widths and token counts that are not multiples of 8/32/tile sizes (e.g. `n_embd = 896`, `n_ff = 4864`, prefill n = 1, 5, 513). Test: every kernel task's `tails` cases.
2. **CPU without AVX2 / `NIBBLE_SIMD=OFF`:** must build and pass the full suite with the scalar paths. Test: CI scalar job (Task 3).
3. **Many threads vs few rows:** `-t 12` with a 2-row matmul or 1 attention head must not deadlock, skip work or race. Test: Task 2 `more threads than chunks`.
4. **Denormals and NaN in activations:** SIMD kernels must not turn a finite input into NaN differently from scalar; NaN propagation is acceptable but must not crash. Test: kernel `edge values` cases.
5. **Benchmark noise:** a bench run on a loaded machine must say so instead of reporting a misleading number. Test: Task 1 `load warning`.

### Task 1: Benchmark harness and baselines

**Files:** Create `cli/cmd_bench.cpp`, `src/bench/membw.{h,cpp}`, `tools/bench_llamacpp.sh`, `bench/results/` (+ `.gitkeep`). Modify `cli/main.cpp`, `cli/commands.h`, `CMakeLists.txt`, `README.md` (usage only).

**Interfaces:**
- `nibble bench -m <model> [-t <list, e.g. 1,2,4,6,8,10,12>] [-p <prompt tokens = 512>] [-n <gen tokens = 128>] [-r <reps = 5>] [--mem] [--out <file.jsonl>]`.
  - `pp<p>`: time to prefill `p` synthetic tokens (token ids `i % n_vocab`, starting with BOS if the model adds one) from an empty cache, as one `forward` call path through `Session` internals (use the internal `Transformer` directly so tokenization is not measured).
  - `tg<n>`: time to decode `n` tokens one at a time after a 1-token prompt, greedy argmax on host logits (exclude sampling cost by using argmax).
  - Warm-up: 1 untimed repetition per configuration; then `r` timed reps; report median and min/max tok/s.
  - `--mem`: streaming read over a 1 GiB buffer (or 4× L3, whichever is larger; `uint64` sum with all threads), median GB/s.
  - Output: a human table on stdout and, with `--out`, one JSON object per measurement: `{"tool":"nibble","commit":<git sha baked in at build>,"model":<file name>,"test":"pp512"|"tg128"|"membw","threads":N,"reps":R,"median":x,"min":x,"max":x,"unit":"tok/s"|"GB/s","load1":x,"date":ISO8601}`.
  - Warn on stderr when `/proc/loadavg` 1-minute load > 2 at start: `warning: load average X — results will be noisy`.
- `tools/bench_llamacpp.sh <model> <threads list> <out.jsonl>` runs `third_party/build/bin/llama-bench -m <model> -p 512 -n 128 -t <each> -r 5 -o json`, converting to the same JSONL schema with `"tool":"llama.cpp"` (record llama.cpp build tag).
- The build bakes the git short SHA into the binary (`NIBBLE_GIT_SHA` compile definition from `git rev-parse --short HEAD` at configure time; `unknown` if not a repo).

- [ ] **Step 5: Baselines.** For each of the five models: `nibble bench -t 1,2,4,6,8,10,12 --mem` and `tools/bench_llamacpp.sh` with the same thread list, back to back. ### Task 6b: Low-overhead parallel dispatch (added by controller ruling R6)

**Why:** after Task 5, single-thread decode is ~1.3–1.6× behind llama.cpp but multi-thread decode collapses past 2 threads (Q4_0 tg16 at t=8: 13.7 vs 119 tok/s). `ThreadPool::parallel_for` takes a mutex and a condition-variable wake per call, ~170 calls per token.

**Files:** Modify `src/thread_pool.{h,cpp}`, `src/backend/cpu/cpu_backend.cpp`, possibly `src/model/transformer.cpp`. Test: `tests/test_thread_pool.cpp`, `tests/alloc_tests.cpp`.

**Interfaces:**
- Keep `parallel_for(n, chunk, FunctionRef)` semantics and its tests. Replace the per-call mutex/condvar handoff with a lower-latency scheme: workers spin on an atomic generation counter for a bounded time (e.g. a few tens of microseconds, measured) with `_mm_pause`, then fall back to a futex/condvar sleep; the caller publishes work with release stores and waits on an atomic completion counter. No heap allocation per call.
- Measure, don't guess: report per-call dispatch latency (a micro-benchmark in `tests/` or `nibble bench --dispatch`) before/after, and `tg16` scaling at t = 1, 2, 4, 6, 8, 10, 12 for Qwen Q4_0, back-to-back with `llama-bench` at the same t.
- If dispatch count itself dominates, reduce it (e.g. run rmsnorm/rope/add on the caller thread when n is small, or merge per-layer ops) — but only with measurements showing the win.
- TSan clean; `more threads than chunks` and the 1000-call test still pass; the pool must not burn CPU indefinitely when idle (spin bound tested: an idle pool's workers go to sleep within the bound).

- [ ] **Step 1–4:** Failing tests (latency/idle-sleep tests may assert only bounds, not exact numbers), implement, pass in Release, Debug+ASan, clang, TSan (`setarch -R`); full e2e passes.
- [ ] **Step 5:** Bench scaling sweep → `bench/results/m6-4b-dispatch.jsonl` with llama.cpp rows taken back-to-back.
- [ ] **Step 6: Commit** `perf(threads): low-latency parallel dispatch`.
