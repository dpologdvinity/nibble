# nibble M0–M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From an empty repo to `nibble run -m qwen2.5-0.5b-instruct-fp16.gguf -p "..."` producing coherent text whose logits match llama.cpp (spec milestones M0–M3).

**Architecture:** Static library `nibble` (public header `include/nibble/nibble.h`, internals under `src/`) plus CLI `nibble`. Model code (`src/model/`) calls a `Backend` interface; `CpuBackend` implements ops by partitioning scalar reference kernels (`src/backend/cpu/ref_ops.*`) over a thread pool. llama.cpp is built separately under `third_party/` and used only by `tools/` to produce golden data.

**Tech Stack:** C++20, g++ 13, CMake ≥ 3.25, Catch2 v3.16.1 (FetchContent), clang + libFuzzer (fuzz target only), Python 3.12 (`tools/gen_unicode_tables.py` only), llama.cpp (reference only).

**Spec:** `docs/superpowers/specs/2026-10-17-nibble-design.md`

**Out of this plan (later plans):** Q8_0/Q4_0 kernels, sampler beyond greedy, chat templates, `nibble bench` (M4–M6); Llama 3.2 / TinyLlama (M5).

## Global Constraints

- C++20; library depends only on the C++ standard library, POSIX `mmap`, and `std::thread`.
- Compile flags: `-Wall -Wextra -Wpedantic -Werror`; option `NIBBLE_NATIVE` (default `ON`) adds `-march=native`; option `NIBBLE_SANITIZE` (default empty) passes `-fsanitize=<value>`.
- All public symbols live in `namespace nibble`; internals in `nibble::gguf`, `nibble::tok`, `nibble::cpu`, `nibble::model`.
- Every user-facing failure throws `nibble::Error` (derives `std::runtime_error`) with a message that names the offending key/tensor/value.
- GGUF input is untrusted (spec §6.1): no read without a bounds check, no size arithmetic without overflow check.
- Generation loop performs no heap allocation (spec §4.1 step 4).
- Model code never dereferences activation memory; activations are allocated with `Backend::alloc` and touched only through backend ops (keeps the Phase 2 CUDA backend possible).
- Downloaded models and golden data go in `models/` (gitignored). Never commit model files.
- E2E thresholds (spec §8.3) are fixed: cosine ≥ 0.999, near-tie gap 1e-3. Do not loosen them without the user's approval.
- Work on branch `feat/m0-m3`, not `master`. Do not push.

## Review Focus

1. **Prompt longer than the prefill batch (512 tokens):** must be processed in chunks with logits identical to processing it in one go. Test: Task 9 `chunked prefill equals incremental`.
2. **Prompt + generation reaching `n_ctx`:** stop with `StopReason::ContextFull`, never write past the KV cache; a prompt that alone has ≥ `n_ctx` tokens throws `nibble::Error`. Tests: Task 10 `context full` and `prompt longer than context throws`.
3. **Invalid UTF-8 prompt:** throws `nibble::Error`, no crash or silent garbage. Test: Task 7 `invalid utf8 throws`.
4. **Empty prompt:** throws `nibble::Error("empty prompt")` instead of running the model on zero tokens. Test: Task 10 `empty prompt throws`.
5. **Valid GGUF the engine can't run** (architecture `phi3`, tokenizer pre `deepseek-llm`, Q4_0 weights before M4): clear `nibble::Error` naming the value. Tests: Task 7 `unsupported pre throws`, Task 9 `unsupported architecture throws` and `unsupported weight dtype throws`.

  - In `nibble::gguf`:
    ```cpp
    enum class ValueType : uint32_t { U8=0, I8=1, U16=2, I16=3, U32=4, I32=5, F32=6, Bool=7, String=8, Array=9, U64=10, I64=11, F64=12 };
    struct Array { ValueType elem_type; std::vector<std::string> str; std::vector<int64_t> i; std::vector<double> f; };
      // String -> str; Bool and all integer types -> i; F32/F64 -> f. Nested arrays rejected.
    using Value = std::variant<int64_t, double, bool, std::string, Array>;
      // integer scalars -> int64_t (U64 > INT64_MAX rejected); F32/F64 -> double
    struct TensorInfo { std::string name; Tensor tensor; uint64_t offset; uint64_t nbytes; };
    class File {
     public:
      static File open(const std::string& path);              // mmap; owns mapping
      static File parse(std::span<const uint8_t> bytes);      // non-owning; bytes must outlive File
      uint32_t version() const;
      const Value* find(std::string_view key) const;          // nullptr if absent
      std::string get_string(std::string_view key) const;     // throws Error if absent/wrong type
      int64_t get_int(std::string_view key) const;
      double get_float(std::string_view key) const;
      const Array& get_array(std::string_view key) const;
      const std::vector<std::pair<std::string, Value>>& metadata() const; // file order
      const std::vector<TensorInfo>& tensors() const;          // file order
      const TensorInfo* find_tensor(std::string_view name) const;
    };
    ```

### Task 4: llama.cpp reference tool and golden data

**Files:**
- Create: `tools/build_llama_cpp.sh`, `tools/llama_cpp_version.txt`, `tools/llama_ref/CMakeLists.txt`, `tools/llama_ref/llama_ref.cpp`, `tools/make_golden.sh`, `tests/golden_file.h`, `tests/tokenizer/corpus.txt`, `tests/e2e/prompts/capital.txt`, `tests/e2e/prompts/code.txt`, `tests/e2e/prompts/chat.txt`, `tests/test_golden_file.cpp`

**Interfaces:**
- Produces:
  - `llama_ref tokenize <model.gguf> <corpus.txt> <out.txt>` — corpus entries are separated by lines that are exactly `====`; the newline before a separator belongs to the separator, not the entry. Output: one line per entry, space-separated token IDs, from `llama_tokenize(vocab, text, len, buf, cap, /*add_special=*/false, /*parse_special=*/false)`.
  - `llama_ref logits <model.gguf> <prompt.txt> <n_gen> <out.bin>` — tokenizes the whole prompt file with `add_special=true, parse_special=true`, evaluates it with logits enabled for every position (use `llama_batch_init`, set `logits[i]=1`), then greedy-decodes `n_gen` tokens one at a time (argmax, lowest index on ties), recording logits after each.
  - Golden file format (little-endian), read by `tests/golden_file.h` as `struct Golden { uint32_t n_vocab, n_prompt, n_gen; std::vector<int32_t> tokens; std::vector<float> logits; std::span<const float> row(size_t i) const; static Golden load(const std::string& path); }`:
    `magic "NBGL"`, `u32 version = 1`, `u32 n_vocab`, `u32 n_prompt`, `u32 n_gen`, `i32 tokens[n_prompt + n_gen]`, `f32 logits[(n_prompt + n_gen) * n_vocab]`. Row `i` is the logits after consuming `tokens[0..i]`; for `i >= n_prompt - 1`, `tokens[i+1] == argmax(row i)`.
  - `tools/make_golden.sh <model-name>` writes `models/golden/<model-name>/{tokenize.txt, capital.bin, code.bin, chat.bin}` using `n_gen = 64`.

### Task 6: Pre-tokenizer

**Files:**
- Create: `src/tokenizer/pretokenize.h`, `src/tokenizer/pretokenize.cpp`
- Test: `tests/test_pretokenize.cpp`

**Interfaces:**
- Consumes: Task 5 `is_letter`, `is_number`, `is_whitespace`, `utf8_decode`.
- Produces: `std::vector<std::string_view> nibble::tok::pretokenize(std::string_view text, int max_digit_run);` — slices of `text`, concatenating to exactly `text`. `max_digit_run` is 1 for qwen2 (3 for llama3 in M5).

The splitter is equivalent to llama.cpp's qwen2 regex:
```
(?:'[sS]|'[tT]|'[rR][eE]|'[vV][eE]|'[mM]|'[lL][lL]|'[dD])|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}{1,MAX}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]+|\s+(?!\S)|\s+
```
At each position `i` over code points, try in order and take the first that matches:
1. `'` followed by `s t m d` (either case), or `re ve ll` (either case per letter) → that 2–3 code point match.
2. If `cp[i]` is not `\r`, `\n`, letter, or number, and `cp[i+1]` is a letter → `cp[i]` plus the letter run. Else if `cp[i]` is a letter → the letter run.
3. Number → up to `max_digit_run` numbers.
4. Let `j = i`; if `cp[j] == ' '` and `cp[j+1]` is "other" (not whitespace, letter, or number), `j++`. If `cp[j]` is other → the run of others from `j`, then any following `\r`/`\n` run.
5. Whitespace run `[i, k)` containing a `\r` or `\n`: match `[i, p+1)` where `p` is the last `\r`/`\n` in the run.
6. Whitespace run of length `n`: if it reaches end of text → match `n`; else if `n ≥ 2` → match `n − 1`.
7. Whitespace run of length `n ≥ 1` → match `n`.
8. Otherwise → single code point.

- [ ] **Step 1: Write failing tests** (exact expected slices, `max_digit_run = 1` unless noted):
  - `"Hello world"` → `{"Hello", " world"}`
  - `"I'm 12345"` → `{"I", "'m", " ", "1", "2", "3", "4", "5"}`; with `max_digit_run = 3` → `{"I", "'m", " ", "123", "45"}`
  - `"DON'T"` → `{"DON", "'T"}`
  - `"a\n\n  b"` → `{"a", "\n\n", " ", " b"}`
  - `"trailing   "` → `{"trailing", "   "}`
  - `"x!!\n"` → `{"x", "!!\n"}`
  - `"  hi"` → `{" ", " hi"}`
  - `"(abc)"` → `{"(abc", ")"}`
  - `""` → `{}`
  - property: for every corpus entry, slices concatenate back to the entry.
